# RelayNet 手动功能测试用例

> 适用版本：v1.x
> 前置条件：已构建 `bin\relayserver.exe` 和 `bin\relayclient.exe`

---

## 一、基础连接测试

### TC-001 中继服务器启动
| 项 | 内容 |
|---|---|
| 用例编号 | TC-001 |
| 测试目的 | 验证中继服务器能正常启动并监听指定端口 |
| 前置条件 | relayserver.exe 存在 |
| 测试步骤 | 1. 打开命令行，执行 `relayserver.exe -listen :19132`<br>2. 观察启动日志 |
| 预期结果 | 输出 `relay server listening on [::]:19132`，进程不退出 |

### TC-002 房主创建房间
| 项 | 内容 |
|---|---|
| 用例编号 | TC-002 |
| 测试目的 | 验证房主模式可成功创建房间 |
| 前置条件 | 中继服务器已启动 |
| 测试步骤 | 1. 启动 `relayclient.exe`<br>2. 填写服务器地址、昵称、房间号、密码<br>3. 选择「房主」模式<br>4. 填写暴露端口（如 7777）<br>5. 点击「连接」 |
| 预期结果 | - 状态变为「已连接」<br>- 成员列表显示自己（带「房主」「你」标签）<br>- 日志显示 `connected: room=xxx id=1 host=true` |

### TC-003 加入者加入房间
| 项 | 内容 |
|---|---|
| 用例编号 | TC-003 |
| 测试目的 | 验证加入者模式可成功加入已存在房间 |
| 前置条件 | 服务器运行中，已有房主创建房间 room1，密码 secret |
| 测试步骤 | 1. 启动第二个客户端<br>2. 填写与房主相同的服务器、房间号、密码<br>3. 选择「加入者」模式<br>4. 填端口转发（如 7777->7777）<br>5. 点击「连接」 |
| 预期结果 | - 加入者状态变为「已连接」<br>- 加入者成员列表显示房主和自己<br>- 房主端成员列表新增该加入者<br>- 两端日志均有 `xxx joined the room` |

### TC-004 正常断开连接
| 项 | 内容 |
|---|---|
| 用例编号 | TC-004 |
| 测试目的 | 验证客户端可正常断开并通知其他人 |
| 前置条件 | 房主 + 加入者都在线 |
| 测试步骤 | 1. 加入者点击「断开」<br>2. 观察房主端 |
| 预期结果 | - 加入者状态变为「未连接」<br>- 房主端成员列表减少该成员<br>- 两端日志均有 `xxx left the room` |

### TC-005 重连
| 项 | 内容 |
|---|---|
| 用例编号 | TC-005 |
| 测试目的 | 验证客户端断开后可重新连接 |
| 前置条件 | 客户端刚断开 |
| 测试步骤 | 1. 点击「连接」再次加入同一房间<br>2. 观察成员列表 |
| 预期结果 | 连接成功，ID 可能变化（一般递增），成员列表正确 |

## 三、数据转发测试

### TC-009 单加入者 UDP 转发
| 项 | 内容 |
|---|---|
| 用例编号 | TC-009 |
| 测试目的 | 验证加入者 -> 房主游戏端口 UDP 转发正常 |
| 前置条件 | 房主 + 加入者在线，房主暴露端口 7777，加入者转发 7777->7777 |
| 测试步骤 | 1. 房主侧用 `nc -ul -p 7777` 或其他工具启动 UDP 监听（或启动游戏服务端）<br>2. 加入者侧用 `nc -u 127.0.0.1 7777` 发送数据<br>3. 观察两端 |
| 预期结果 | 房主端能收到加入者发送的数据，加入者能收到房主回复的数据 |

### TC-010 多加入者互不干扰
| 项 | 内容 |
|---|---|
| 用例编号 | TC-010 |
| 测试目的 | 验证多个加入者的数据各自独立，不会串线 |
| 前置条件 | 1 个房主 + 2 个加入者（加入者A、加入者B） |
| 测试步骤 | 1. 加入者A发送消息 "hello from A"<br>2. 加入者B发送消息 "hello from B"<br>3. 房主分别回复 |
| 预期结果 | - 房主能区分两个不同来源<br>- 加入者A只收到给A的回复，加入者B只收到给B的回复 |

### TC-011 大包转发（接近 MTU）
| 项 | 内容 |
|---|---|
| 用例编号 | TC-011 |
| 测试目的 | 验证大数据包（如 1400 字节）能正常转发 |
| 前置条件 | 房主 + 加入者在线 |
| 测试步骤 | 1. 加入者发送 1400 字节数据（超出游戏常见包大小）<br>2. 房主回复相同数据 |
| 预期结果 | 数据完整到达，无截断、无丢失（允许偶发UDP丢包，但单次测试应能收到） |

## 屏幕音频与音画同步实机检查

- 两台 Windows 客户端均使用新版，加入同一房间。发送端在屏幕共享区域开启“同时共享电脑声音”，分别选择低、中、高后开始共享；接收端选中发送成员，确认画面和电脑声音一起播放，停止共享后声音一起停止。
- 发送端播放带同步闪光与短音的视频。分别在 30、60、120 FPS 设置下，以接收端同时录制画面和声音的方法测量偏差；持续播放至少 10 分钟，记录开始和结束的偏差，检查没有持续漂移。自动测试没有覆盖真实声卡与显示设备延迟。
- 在发送端静音几秒后恢复播放，确认声音恢复后仍跟随同一画面时间轴。短暂中断网络后恢复，确认两路一起重新缓冲，不播放积压旧声音。
- 两名成员同时共享，接收端切换观看成员，确认只能听到当前所选屏幕的声音；本地预览保持静音。


### 中途观看屏幕的自动实机检查

默认测试不采集桌面、不初始化声卡。需要在 Windows 上验证真实采集、中继、H.264 参考帧追赶与声音播放时钟时，可运行：

```powershell
$env:RELAYNET_LIVE_SCREEN_TEST = "1"
go test ./internal/media -run TestLiveScreenPlaybackStartup -v -count=1 -timeout=25s
go test ./internal/tunnel -run TestLiveScreenLateViewer -v -count=1 -timeout=45s
Remove-Item Env:RELAYNET_LIVE_SCREEN_TEST
```

测试仅在本机临时中继转发桌面和电脑声音，接收音量为零；不保存屏幕或音频文件。它检查的是播放调度，不能代替对声卡和显示器真实延迟的测量。

### GPU 编码与真实观看窗口帧率检查

```powershell
. ./prepare-client-build.ps1
$env:RELAYNET_REQUIRE_HW_CODEC = "1"
go test -modfile $clientModFile ./internal/media -run 'TestRequiredHardwareH264|TestHardwarePipeline|TestCaptureEncoderUsesMTA' -v -count=1 -timeout=60s
Remove-Item Env:RELAYNET_REQUIRE_HW_CODEC
$env:RELAYNET_LIVE_GUI_TEST = "1"
go test -modfile $clientModFile ./cmd/relayclient -run TestLiveScreenGUI -v -count=1 -timeout=90s
Remove-Item Env:RELAYNET_LIVE_GUI_TEST
```

第一项要求可用的 GPU H.264 编码器，检查 1080p/120 FPS 单帧编码时间、图像尺寸和采集时间戳。第二项会开启临时观看窗口并自动关闭，在本机中继传输 2160p/120 FPS 设置的视频与中档电脑声音，同时模拟已暂停的本地预览。测试声音静音；记录的是界面提交画面的速率，未测量显示器物理呈现或音画的物理偏差。

### 房间投票和否决

- 两人房间中，成员对房主发起投票；应自动进入 30 秒否决期，原房主弹窗一次，倒计时持续更新。
- 4 个有资格的投票人必须至少 3 票赞成，2 票不能通过；目标无投票按钮，发起人已自动赞成，已投票者不能改票。
- 房主明确点击否决后，目标及当前房主身份不变；关闭弹窗后不得自动否决或重新弹窗，30 秒后由发起人接任，原房主保持连接。
- 投票踢普通成员执行后，目标断开，其余成员看到发起人成为房主；新房主可直接踢人，旧房主失去管理权。
- 原房主的游戏服务仍在线时，移交管理权后 UDP/TCP 流量仍到原服务电脑；不能把原有游戏连接改发给新管理者。
- 投票 60 秒未过半则结束；迟到的投票/否决无效。发起人或目标退出取消本轮，其他人退出不更改固定门槛；新加入者不参与。
- 投票期间断开/重新连接，旧窗口的确认不可作用到新连接；乱序状态、重复投票和重复请求不能恢复旧权限或再次执行。
- 不更新服务端时应提示暂不可用，不能显示已发起或已通过。
